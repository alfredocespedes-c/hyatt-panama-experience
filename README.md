# Hyatt + PepsiCo QR Experience Prototype

A mobile-first, static Vite/React experience that moves through an original procedural React Three Fiber architectural model into a four-question response flow. The model is **conceptual**: its abstract Panama blocks and two-tower hotel massing are not a survey, digital twin, or representation of a precise building design. No official logos, hotel photography, proprietary plans, Google Earth imagery, third-party models, or video are included.

The WebGL scene is lazy-loaded and code-generated from primitive geometry. Browsers without WebGL keep the lightweight CSS/SVG architectural fallback. `prefers-reduced-motion` resolves directly to a static ballroom scene rather than playing the camera flight.

## Run locally

```bash
npm install
npm run dev
```

Quality gates:

```bash
npm test
npm run build
```

With no environment variables, submissions use **demo mode** and are stored in the browser under `arrival-demo-submissions`. Form progress is separately persisted under `arrival-response-draft` and removed after a successful submission.

## Production data with Supabase

Copy `.env.example` to `.env.local` and provide the project's public REST values:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

Vite values are compiled into the public frontend. Use only the Supabase **anon/public key** here—never a service-role key, database password, or other secret.

Create the table and an insert-only anonymous policy in the Supabase SQL editor:

```sql
create table public.event_responses (
  id bigint generated by default as identity primary key,
  general_manager text not null check (char_length(general_manager) between 1 and 200),
  food_beverage_director text not null check (char_length(food_beverage_director) between 1 and 200),
  hotel_name text not null check (char_length(hotel_name) between 1 and 200),
  email_contact text not null check (email_contact ~* '^[^[:space:]@]+@[^[:space:]@]+\.[^[:space:]@]{2,}$'),
  user_agent text,
  submitted_at timestamptz not null default now()
);

alter table public.event_responses enable row level security;

grant insert on table public.event_responses to anon;
grant usage, select on sequence public.event_responses_id_seq to anon;

create policy "event attendees can submit responses"
on public.event_responses
for insert
to anon
with check (
  char_length(general_manager) between 1 and 200
  and char_length(food_beverage_director) between 1 and 200
  and char_length(hotel_name) between 1 and 200
  and char_length(email_contact) between 3 and 320
);
```

Do not create anonymous `select`, `update`, or `delete` policies. Export responses from the authenticated Supabase dashboard. Before launch, the event owner should approve the privacy notice and define retention/deletion rules.

## Deploy to GitHub Pages

The Vite base is relative (`./`), so the build works at a repository subpath.

1. Push the repository to GitHub.
2. In **Settings → Pages**, set **Source** to **GitHub Actions**.
3. Add repository variables named `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` if production storage is required. The anon key is public by design, but repository variables keep environment configuration explicit.
4. Push to `main`; `.github/workflows/deploy.yml` tests, builds, and publishes `dist/`.
5. Open the Pages URL on iOS Safari and Android Chrome before printing the QR code.

For a fork or custom branch, update the workflow trigger. No server-side code runs on GitHub Pages.

## QR workflow

1. Deploy and copy the final HTTPS Pages URL.
2. Test the URL in a clean/private mobile browser on both Wi-Fi and cellular data.
3. Generate a high-error-correction QR code (level Q or H) with a reputable offline or approved campaign tool.
4. Print a test at final physical size. Keep a quiet zone of at least four modules and aim for at least 25 mm square.
5. Scan from the expected attendee distance and lighting. Confirm the full tap → journey/skip → four questions → completion path.
6. Lock the public URL before producing event signage; changing a static QR destination requires reprinting unless an approved managed redirect is used.

## Replacing the conceptual model or using approved video

The current sequence is original procedural geometry with a CSS/SVG fallback. A future approved GLB belongs at `public/models/hotel-concept.glb`; `src/scene/ImmersiveModel.tsx` contains the replacement seam. Preserve the current origin/scale, run geometry and texture compression, and document provenance in `public/models/README.md`.

If licensed footage and authorized marks are supplied later:

- Keep the abstract sequence as a low-bandwidth and reduced-motion fallback.
- Export an H.264 MP4 (`yuv420p`, `faststart`) plus WebM where testing supports it.
- Target 720×1280 portrait, 24–30 fps, 6–10 seconds, and roughly 1.5–3 MB for event connectivity.
- Strip unused audio, or add captions and an explicit mute control if audio is essential.
- Example compression command:

```bash
ffmpeg -i approved-source.mov -vf "scale=720:-2:flags=lanczos,fps=24" \
  -c:v libx264 -profile:v main -crf 24 -preset slow -pix_fmt yuv420p \
  -movflags +faststart -an public/arrival.mp4
```

Record the source, license, approver, edit date, and compression settings beside every replacement asset. Do not add official Hyatt or PepsiCo marks until written authorization and production-ready files are supplied.
